## The prompt preservation rule

Prompts are preserved verbatim and never reconstructed after the fact. In practice:

1. The prompt file is saved as part of the assignment, before or as the session runs, its sha256 is recorded with the step, and the file is stored in `submission-pack/provenance/starter-author/` or `submission-pack/provenance/pack-writer/` as applicable.
2. The preserved file is not edited afterward. If a prompt must change, that is a new step with a new preserved file and a new hash. The old file is kept.
3. If the preserved prompt file is lost, the row says so (`PENDING` with the loss recorded) and the step is treated as unprovenanced. Nobody rewrites "the prompt we must have used" from the output, from memory or from a chat retelling. An output without its preserved prompt can still ship if the owner decides, but its provenance cell stays `PENDING` and any authorship claim on it stays weak by record, not by wording.
4. Event log files get the same treatment: preserved as written in the session's provenance folder, sanitized for sharing by a separate scrubbing step whose output is a new file, never by editing the original in place.
5. Machine-written records are never reproduced by hand. If the tool that writes a step record or a session file hangs or is missing, the cell stays `PENDING` and the blocker goes in `READINESS.md`.
